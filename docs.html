BrutalKit is a lightweight Neo-Brutalist CSS component library. It gives you a consistent visual foundation while keeping your HTML, application architecture, and JavaScript in your hands.

CSS-firstVanilla JavaScriptMIT licenseNo framework dependency
01 / START HERE

Getting started

Include the compiled stylesheet in your document. The CDN URL below tracks main; pin a release tag once you publish one for reproducible deployments.

HTML · CDN
<link
  rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/ravvdevv/brutal-kit@main/dist/brutal.min.css"
/>

Use the source stylesheet locally if you prefer to manage assets yourself:

HTML · LOCAL FILE
<link rel="stylesheet" href="./dist/brutal.css" />

Most components are CSS-only. For tabs and dialog open/close triggers, load the optional module:

HTML · OPTIONAL INTERACTIONS
<script type="module" src="./src/brutal.js"></script>
02 / COMPONENTS

Buttons

Buttons use native button semantics. Choose a visual variant and size with modifier classes. Use a real disabled attribute when an action is unavailable.

HTML
<button class="bk-button" type="button">Default</button>
<button class="bk-button bk-button--primary" type="button">Primary</button>
<button class="bk-button bk-button--blue" type="button">Blue</button>
<button class="bk-button bk-button--danger" type="button">Danger</button>
<button class="bk-button bk-button--sm" type="button">Small</button>
<button class="bk-button bk-button--lg" type="button">Large</button>
<button class="bk-button bk-button--block" type="button">Full width</button>
Note: .bk-button--block sets width to 100%. Keep the native button type explicit inside forms to avoid accidental submission.

Cards

Cards are content containers. The flat modifier removes the offset shadow when a quieter surface is more appropriate.

✳

A useful card

A small content surface with a clear hierarchy and a little bit of attitude.

Flat variation

Same border and surface, without the offset shadow.

HTML
<article class="bk-card">
  <span class="bk-card__icon" aria-hidden="true">✳</span>
  <h3 class="bk-card__title">Card title</h3>
  <p class="bk-card__description">Supporting text goes here.</p>
</article>

<article class="bk-card bk-card--flat">...</article>

Form controls

Pair every control with a visible label. Hint and error text can be connected using aria-describedby.

This is how your name appears to others.
That username is unavailable.
HTML
<div class="bk-field">
  <label class="bk-label" for="email">Email address</label>
  <input class="bk-input" id="email" type="email"
    aria-describedby="email-hint" />
  <span class="bk-field__hint" id="email-hint">
    We will only use this for account updates.
  </span>
</div>

<textarea class="bk-textarea" aria-label="Message"></textarea>
<select class="bk-select" aria-label="Choose a role">...</select>

Alerts

Alerts are static feedback regions. Choose an appropriate live-region role based on the urgency and timing of the message.

Heads up

Here is some useful information.

Saved

Your changes have been saved.

Check this

One item needs your attention.

Something failed

We could not complete that action.

HTML
<div class="bk-alert bk-alert--success" role="status">
  <div>
    <strong class="bk-alert__title">Saved</strong>
    <p class="bk-alert__body">Your changes have been saved.</p>
  </div>
</div>

Checkboxes & switches

These styles preserve native input behavior. The .bk-switch class currently styles the native control; it does not turn a checkbox into a custom animated switch.

HTML
<label class="bk-check">
  <input class="bk-checkbox" type="checkbox" checked>
  Receive product updates
</label>

<label class="bk-check">
  <input class="bk-switch" type="checkbox">
  Enable notifications
</label>

Tabs

Tabs require the tablist, tab, and tabpanel relationships shown below. The optional JavaScript activates panels, supports arrow keys, Home and End, and isolates nested tab groups.

This is the first panel. Use the arrow keys to move between tabs.
This is the second panel. Keyboard focus follows the active tab.
Disabled example panel.
HTML
<div data-bk-tabs>
  <div class="bk-tabs" role="tablist" aria-label="Account settings">
    <button class="bk-tab" id="tab-profile" role="tab"
      aria-selected="true" aria-controls="panel-profile">
      Profile
    </button>
    <button class="bk-tab" id="tab-security" role="tab"
      aria-selected="false" aria-controls="panel-security" tabindex="-1">
      Security
    </button>
  </div>
  <section class="bk-tabpanel" id="panel-profile"
    role="tabpanel" aria-labelledby="tab-profile">...</section>
  <section class="bk-tabpanel" id="panel-security"
    role="tabpanel" aria-labelledby="tab-security" hidden>...</section>
</div>
The data-bk-tabs attribute is the initialization boundary. Each tab needs a unique ID and a matching aria-controls target.

Accordion

Accordions use the browser's native details and summary elements. No JavaScript is required.

Can I use this without JavaScript?
Yes. The CSS components work independently. Only tabs and dialog triggers need the optional JavaScript module.
Can I customize the colors?
Yes. Override the documented CSS custom properties in your own stylesheet.
HTML
<details class="bk-accordion">
  <summary class="bk-accordion__summary">Question</summary>
  <div class="bk-accordion__content">Answer goes here.</div>
</details>

Dialog

Use the native HTML dialog element. BrutalKit's optional JavaScript connects trigger and close buttons, opens the dialog modally, and restores focus to the trigger after closing.

HTML
<button class="bk-button" data-bk-dialog-open="confirm-dialog">
  Open dialog
</button>

<dialog class="bk-dialog" data-bk-dialog id="confirm-dialog"
  aria-labelledby="confirm-title">
  <h2 class="bk-dialog__title" id="confirm-title">Confirm action</h2>
  <p class="bk-dialog__body">Continue with this action?</p>
  <button class="bk-button" data-bk-dialog-close>Cancel</button>
</dialog>
The dialog must have data-bk-dialog. Use a unique ID matching the trigger's data-bk-dialog-open value. Provide an accessible name with aria-labelledby or aria-label.

Tooltip

Tooltips are CSS-only. Add a data-bk-tooltip attribute to an element with a keyboard focus target. Keep essential information visible elsewhere.

HTML
<button class="bk-button bk-tooltip"
  type="button" data-bk-tooltip="A short helper message">
  Hover or focus me
</button>

Accessibility

BrutalKit provides accessible styling and interaction foundations, but the consuming application is responsible for correct semantics, labels, validation, and complete user flows.

  • Use native elements and meaningful labels.
  • Keep visible keyboard focus. Do not remove outlines without an equivalent.
  • Connect help and error text using aria-describedby.
  • Use the correct live-region role for dynamic status and error messages.
  • Respect reduced-motion preferences and avoid conveying state through color alone.
  • Test your complete interface with keyboard and assistive technology.
SCREEN-READER-ONLY TEXT
<span class="bk-visually-hidden">Opens in a new tab</span>

Customization

Override the CSS custom properties after the BrutalKit stylesheet. You can change the palette, border weight, shadows, radius, font stack, and spacing tokens.

CSS
:root {
  --bk-bg: #f7f6f2;
  --bk-surface: #ffffff;
  --bk-ink: #20233b;
  --bk-muted: #686b7e;
  --bk-purple: #7055d9;
  --bk-purple-dark: #5940bf;
  --bk-yellow: #ffc93c;
  --bk-blue: #a7c8ff;
  --bk-pink: #ffab7e;
  --bk-success: #9ff0c2;
  --bk-danger: #ffd0cb;
  --bk-lilac: #cfc7ff;
  --bk-border-width: 2px;
  --bk-shadow: 6px 6px 0 var(--bk-ink);
  --bk-shadow-sm: 3px 3px 0 var(--bk-ink);
  --bk-radius: 10px;
  --bk-font: "DM Sans", sans-serif;
  --bk-font-display: "Manrope", "DM Sans", sans-serif;
}
